# 프로젝트 로그 기록

이 프로젝트는 결정과 시행착오를 로그로 남기는 것이 제출물의 일부다. 로그가 정확해야 PRD·테스트 보고서·회고의 근거가 되므로, 번호·형식·요약표를 매번 같은 방식으로 맞춘다.
사용자는 개발자가 아니므로 쉬운 한국어로 쓰고, 전문 용어는 괄호로 풀어 쓴다.

## 1. 어느 로그에 쓸지 고르기

| 상황 | 로그 | 번호 |
|---|---|---|
| 선택지가 2개 이상이었고 그중 하나를 골랐다 (범위, 방식, 위치, 이름 등) | logs/decision-log.md | D-번호 |
| 빌드·배포·API·화면 동작이 기대와 달랐다 | logs/success-fail-log.md | F-번호 |
| 기능이 처음 동작했다, 오류를 해결했다, 목표(예: 분량, 테스트 통과)를 달성했다 | logs/success-fail-log.md | S-번호 |

- 커밋·푸시처럼 늘 되는 일은 적지 않는다 (기록할 가치가 없고 로그만 길어진다).
- 이미 기록된 결정을 바꾸면 예전 기록은 지우지 말고, 새 번호로 "(D-xx 변경)"을 제목에 붙여 추가한다. 결정이 어떻게 바뀌었는지가 그대로 남아야 하기 때문이다.

## 2. 다음 번호 찾기

추측하지 말고 파일에서 가장 큰 번호를 찾아 1을 더한다.

```bash
grep -oE '^## D-[0-9]+' logs/decision-log.md | tail -1
grep -oE '^## \[(실패|성공)\] [FS]-[0-9]+' logs/success-fail-log.md
```

F와 S는 번호를 따로 센다 (F-06 다음 실패는 F-07, S-05 다음 성공은 S-06).

## 3. 형식

### 의사결정 로그 (파일 맨 아래에 추가)

```markdown
## D-23 | 2026-11-25 | 강의 키워드 질문을 확인형으로 변경 (F-03 규칙 보완)
- 결정: 고른 것을 한두 문장으로
- 대안: 고르지 않은 선택지들 (/ 로 구분)
- 이유: 왜 골랐는지. 사용자가 이유를 말하지 않았으면 "확인 필요"로 쓰고 사용자에게 묻는다
- 영향: 바뀐 파일·문서·테스트, 남은 한계
```

- 날짜는 오늘 날짜(YYYY-MM-DD).
- **이유를 지어내지 않는다.** 사용자가 고른 이유를 모르면 "이유: 확인 필요"로 남기고 물어본다. 제안한 쪽이 Claude였다면 제목에 "(Claude 제안, 본인 확인)"을 붙인다.

### 성공·실패 로그

두 군데를 고친다. **맨 위 "한눈에 보기" 표에 한 줄**, **본문 맨 아래에 기록**. 표를 빠뜨리면 요약과 본문이 어긋나므로 둘 다 꼭 고친다.

요약표 줄 (표의 마지막 줄 다음에 추가):
```markdown
| F-07 | 11/25 | 실패 | 한 줄 요약 |
| S-07 | 11/25 | 성공 | 한 줄 요약 |
```

실패 기록:
```markdown
## [실패] F-07 | 2026-11-25 | 제목
- **시도:** 무엇을 하려고 했는지
- **결과:** 실제로 무슨 일이 일어났는지 (오류 문구가 있으면 그대로)
- **원인:** 왜 그랬는지 (모르면 "확인 필요")
- **다음 조치:** 무엇을 할 것인지
```

실패를 해결하면 그 기록 끝에 `- **해결:** …`을 추가하고, 요약표의 결과 칸을 `실패 → 해결`로 바꾼다.

성공 기록:
```markdown
## [성공] S-07 | 2026-11-25 | 제목
- **시도:** 무엇을 했는지
- **결과:** 확인한 사실 (숫자·문구 위주)
- **잘된 점:** 다음에도 쓸 방법
```

이모티콘은 쓰지 않는다 (사용자가 글자 표시를 원함).

## 4. 커밋: 로그만 따로

로그는 코드·문서와 **반드시 다른 커밋**으로 남긴다. 한 커밋에 섞이면 "무엇을 왜 바꿨는지"가 흐려지고, 실제로 파일 이동이 로그 커밋에 섞인 적이 있다(D-21).

1. 커밋 전 `git status --short`로 미리 올려 둔(staged) 다른 파일이 없는지 확인한다. 있으면 그 파일을 먼저 따로 커밋하거나 사용자에게 알린다.
2. 로그 파일만 지정해서 올린다: `git add logs/decision-log.md logs/success-fail-log.md`
3. 메시지는 `log:` 접두어 + 한국어 한 줄.
   - 예: `log: D-23~D-26 확인형 질문·카테고리·대화 기록 결정, S-06 기록`
   - 예: `log: F-05 패널이 저장 버튼 가림, F-06 수정 요청 미반영 해결 기록`
4. 커밋·푸시는 사용자가 원할 때 한다. 묻지 않고 푸시하지 않는다.

## 5. 마치고 알려 줄 것

사용자에게 짧게 보고한다: 어떤 번호를 어디에 추가했는지, "확인 필요"로 남긴 것이 있는지(있으면 무엇을 물어볼지), 커밋했는지 여부.
