# 블로그 리디자인

zn 블로그 화면을 다시 꾸미는 절차. 순서는 **시안 → 선택 → 적용 → 확인 → 승인 → 배포**이고, 단계를 건너뛰지 않는다. 사용자에게는 한국어로 답하고, 사용자는 개발자가 아니므로 쉬운 말로 설명한다.

## 기본 정보

- 코드 위치: `C:\Users\user\Desktop\AIPM 소스코드\blog`. 빌드 도구 없이 HTML, `style.css`, `main.js`(ES 모듈)로 이루어져 있다.
- 페이지: `index.html`(첫 화면), `posts.html`(글 목록), `post.html`(글 상세), `write.html`(글쓰기), `login.html`(관리자 로그인), `stats.html`(조회수, 관리자 전용).
- 글 데이터는 Firebase(Firestore)에서 오고, 화면 일부는 `main.js`가 직접 만든다.
  - 예: 첫 화면 최근 글(`.recent-row`), 추천 글, 카테고리 글 수, 글 목록 줄(`.post-row`).
  - 디자인 이름(class)을 바꾸면 `main.js`의 해당 코드도 함께 바꿔야 한다.
- `data-*` 속성(예: `data-recent`, `data-featured`, `data-stat-total`, `data-weather`, `data-cat`, `data-admin-only`)은 `main.js`가 화면을 찾는 표시다. **지우거나 이름을 바꾸지 않는다.** 위치는 옮겨도 된다.
- 기본 색은 `style.css` 맨 위 `:root`에 있다. 강조색 `--accent: #1F4FC7`, 카테고리 색은 `--blue`(기획), `--peach`(디자인), `--mint`(회고)이다. 글꼴은 Noto Sans KR(본문)과 IBM Plex Sans KR(제목)이다.
- 첫 화면 전용 스타일은 `body.home` 아래(`.home …`)에 모여 있다.

## 1. 요청 정리

- 무엇을 바꿀지가 불분명하면 짐작하지 말고 선택지로 묻는다. 확인할 것은 다음과 같다.
  - **대상:** 첫 화면만인지, 특정 페이지인지, 전체인지.
  - **느낌:** 예를 들어 "따뜻하게", "잡지처럼", "더 미니멀하게".
  - **지킬 것:** 브랜드 색 유지, 날씨·고양이 칸 유지 등.
- 이 단계에서는 코드를 고치지 않는다.

## 2. 시안 만들기 (코드 반영 없음)

- `artifact-design` 스킬을 먼저 불러온 뒤 시안을 Claude 아티팩트로 만든다. 사용자가 원하면 2개를 만들어 비교하게 한다.
- 시안은 Tailwind CSS(CDN)로 만들어도 된다. 실제 사이트에는 Tailwind를 넣지 않고, 4단계에서 `style.css`로 옮겨 쓴다.
- 실제 블로그의 글 제목, 카테고리, 글 수를 써서 시안을 현실감 있게 만든다.
- 아티팩트는 외부 이미지를 막는다. 사진은 data URI로 넣는다(로컬에서 받아 base64로 변환).
- 시안 파일은 scratchpad에 둔다.
- 링크를 주면서 "코드에는 아직 반영하지 않았다"고 분명히 말한다.

## 3. 선택 받기

- 사용자가 고른 시안과 추가로 고칠 점을 확인한다. 시안 단계에서 몇 번 고쳐도 괜찮다.

## 4. 실제 코드에 적용

- 시안의 색, 배치, 크기를 **`style.css`의 일반 CSS로 옮긴다.** 대상 페이지 범위로 묶어 다른 페이지에 번지지 않게 한다(예: `.home …`).
- HTML 구조를 바꿀 때는 `data-*` 표시를 유지한다. `main.js`가 만드는 조각은 `main.js`에서 class와 구조를 바꾼다.
- 공통 부분(머리글, 바닥글, `.section-head` 등)을 바꾸면 다른 페이지도 영향을 받는다. 그 페이지들도 확인 목록에 넣는다.
- **휴대폰에서 보기 쉽게 하는 것이 기본이다.** 640px 이하 규칙에 다음을 챙긴다.
  - 양옆 여백은 16px이다.
  - 버튼, 링크 등 누르는 곳은 높이 44px 이상이다.
  - 입력칸 글자는 16px 이상이다. 더 작으면 아이폰이 입력할 때 화면을 확대한다.
  - 여러 칸 배치는 한 줄에 하나씩 쌓는다.
  - 큰 장식 글자(예: 첫 화면 `zn.` 워드마크)는 화면 밖으로 넘치지 않게 고정 크기로 줄인다.
- 자주 생기는 실수: `.home .hero p` 같은 넓은 규칙이 안쪽 상자의 `p`까지 바꾼다(글자 크기, `max-width` 등). 새 상자 안의 문단은 더 구체적인 선택자로 따로 정한다.

## 5. 확인 (PC·휴대폰)

1. 로컬 서버를 연다: `preview_start`에 `{name: "blog"}`를 넘긴다(`AIPM 소스코드\.claude\launch.json`, 포트 8123).
   - 날씨·고양이 칸이 보이게 하려면 `blog/widgets.json`이 있어야 한다. 없으면 실제 사이트에서 받아 둔다(`.gitignore` 대상이라 커밋되지 않는다).
     ```bash
     curl -s -o widgets.json https://jinajung01.github.io/blog/widgets.json
     ```
2. **PC 확인:** `resize_window`로 `width 1280`, 높이는 페이지 길이만큼(예: 2600) 맞춘다. 새로고침하고 3~4초 기다린 뒤(글 데이터 로딩) `computer` screenshot을 찍는다.
3. **휴대폰 확인:** `resize_window`로 `width 375`, 높이는 페이지 길이만큼(예: 3400) 맞춘 뒤 같은 방법으로 찍는다.
4. `javascript_tool`로 숫자를 확인한다.
   - 가로 넘침: `document.documentElement.scrollWidth > innerWidth`가 false여야 한다.
   - 화면 밖으로 나간 요소: `getBoundingClientRect().right > innerWidth`인 요소가 없어야 한다.
   - 누르는 곳: 보이는 `a`, `button`, `input` 중 높이가 40px 미만인 것이 없어야 한다.
   - 내용 채움: 글 목록, 기록 현황 등이 실제로 채워졌는지 본다.
   - 오류: `read_console_messages`(onlyErrors)에 아무것도 없어야 한다.
5. 공통 부분을 바꿨다면 `posts.html` 등 다른 페이지도 휴대폰 폭에서 확인한다.
6. **`post.html`(글 상세)는 열지 않는다.** 관리자가 아닌 브라우저로 열면 조회수가 1 올라간다. 확인이 꼭 필요하면 먼저 사용자에게 알린다.
7. 헤드리스 Edge 캡처는 Firebase 데이터가 로드되지 않으므로 쓰지 않는다. 내장 브라우저 캡처를 쓴다.
8. 끝나면 `resize_window`를 `preset: "desktop"`으로 되돌리고 `preview_stop`으로 서버를 끈다.

## 6. 보여 주고 승인 받기

- PC, 휴대폰 캡처를 `SendUserFile`로 보낸다(`display: "render"`).
- 다음을 쉬운 말로 짧게 정리한다.
  - 바뀐 것
  - 휴대폰에서 보기 쉽게 한 것
  - 확인한 것과 확인하지 못한 것(예: 글 상세 페이지)
- **커밋과 배포는 아직 하지 않는다.** 배포할지 묻는다.
- 사용자가 "원래대로"라고 하면 해당 변경만 되돌리고, 다른 수정(버그 수정 등)은 유지한다.

## 7. 배포

- 사용자가 배포를 승인하면 `blog-deploy` 스킬을 불러 그 절차대로 진행한다(버전 번호 올리기 → 한국어 커밋 → push → 실제 사이트 확인).
- 커밋 타입은 화면 디자인 변경이면 `스타일`이다.
