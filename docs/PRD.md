# PRD v1.1 — 수업 기록 → 블로그 초안 정리 챗봇

## 1. 기본 정보
**버전** v1.1 · **작성일** 2026-11-24 · **작성자** 정지나 · **관련 문서** https://jinajung01.github.io/blog/ · TEST_REPORT.md · decision-log.md

## 2. 개요
강의 메모는 키워드로만 남고 실습은 기록되지 않아 수업이 끝나면 맥락을 잃는 문제를, 블로그 글쓰기 화면의 **관리자 전용 챗봇**으로 푼다.
메모를 넣으면 빠진 맥락만 최대 3개 묻고, 답을 반영한 글 초안(제목·요약·본문·카테고리·태그)을 글쓰기 칸에 채운다.

## 3. 문제
**3.1 데스크리서치**
**3.1.1 SWOT** 강점: 글 저장되는 블로그 운영 중, 사용자=본인 · 약점: 2일·1인·무료 한도 · 기회: 무료 AI, 기록이 포트폴리오가 됨 · 위협: 범용 AI 챗봇, AI가 지어낼 위험

**3.1.2 3C**
- 고객: 종이 노트에 손으로 적는 본인(블로그엔 정리 글 없음) · 자사: 관리자 전용 글쓰기가 있는 블로그 · 대안: 범용 AI 챗봇(질문 없이 그럴듯하게 채움), 노트 앱 AI 요약(적은 것만 요약), 녹음 요약 앱(실습은 못 남김)
- → 차별점: **빠진 맥락을 질문으로 채우고, 지어내지 않으며, 블로그 글로 바로 넣는다**

**3.2 문제 발굴**
| 문제 | 타깃 | 솔루션 방향 |
|---|---|---|
| ① 강의 메모가 키워드뿐이라 뜻을 잃음 | 강의 듣는 본인 | 설명 없는 키워드만 질문 |
| ② 실습 중엔 기록을 못 함 | 실습하는 본인 | 만든 것·순서·막힌 점·배운 점 질문 |
| ③ 정리 부담으로 건너뜀 | 수업 직후의 본인 | 초안 자동 생성 후 확인 |

**3.3 문제 검증**
- **계획:** 사용자가 본인이라 설문 대신 **본인 기록 점검** — 지금까지 들은 강의 노트(종이) 21회 중 OT 1회를 뺀 20회
- **결과(1차 관찰):** 하루 키워드 약 7개(날마다 차이 있음), 대부분 설명 없이 단어만 적힘(예: IA, RICE, UTM).
  실습은 도구 이름만 남고 순서·막힌 점은 거의 없음. 아래 지표의 정확한 비율은 확인 필요
- **지표:** 설명 기록률(설명 붙은 키워드 ÷ 전체) · 맥락 유지율(지금 설명 가능한 키워드 ÷ 전체) · 실습 기록률(기록 남은 회차 ÷ 실습 회차) · 재현 가능률(다시 따라 할 수 있는 실습 ÷ 전체)

**3.4 문제 최종 정의**
**3.4.1 우선순위 (모스코우)** 꼭 필요 F1·F2·F3·F4·F6·F8 / 있으면 좋음 F5·F7·F9 / 나중에 회고 글(근거 약함, D-07)·섞인 입력 글 분리 /
안 함 스크린샷·파일 입력, 카테고리 구조 변경, 지난 노트를 글로 옮기기(앞으로의 수업부터 사용)

**3.4.2 문제 최종 정의** 수업을 정리하는 수강생(관리자 본인)은 강의 중에는 메모가 짧게 남고
실습 중에는 기록할 수 없어, 수업이 끝난 뒤 맥락을 잃거나 아예 남지 않은 내용을
복습과 포트폴리오에 활용하지 못한다.

## 4. 해결 방안
**4.1 솔루션 정의** 기억이 남아 있을 때 짧은 질문 몇 개로 빠진 맥락을 채워, 다시 읽어도 이해되는 블로그 글을 남기게 한다.

**4.2 AS-IS / TO-BE**
| 구분 | AS-IS (지금) | TO-BE (챗봇 도입 후) |
|---|---|---|
| 강의 | 종이 노트에 키워드만 남아 나중에 뜻을 모름 | 설명 없는 키워드를 챗봇이 질문 → 들은 맥락이 담긴 글 |
| 실습 | 손이 묶여 기록이 없음 | 만든 것·순서·막힌 점·배운 점 질문 → 실습 기록 |
| 정리 | 제목·요약·태그를 직접 써야 해 건너뜀 | 초안 자동 생성 → 확인·수정만 |
| 블로그 | 수업 정리 글 없음 | 글쓰기 화면 옆 패널에서 바로 글쓰기 칸에 넣어 저장 |

컨셉: 대신 써 주는 AI가 아니라 **빠진 맥락을 물어봐 주는** 수업 기록 도우미 · 타깃: 수업 직후의 관리자 본인 · BM: 없음(무료 등급)

**4.3 예상 성과 (OKR)**
**O** 다시 읽어도 이해되는 수업 기록이 남는다 · **KR1** 맥락 유지율 상승 · **KR2** 실습 기록률 상승 · **KR3** 수업 1회 정리 시간 단축 (목표치는 3.3 점검 후, 확인 필요)

## 5. 가설 및 지표
**5.1 핵심 지표**
| 가설 | 측정 지표 | 현재 |
|---|---|---|
| H1 설명 없는 키워드만 질문하면 맥락이 남는다 | 맥락 유지율 | 확인 필요 |
| H2 회상 질문을 주면 실습 기록이 남는다 | 실습 기록률 | 확인 필요 |
| H3 형식을 자동으로 만들면 정리 시간이 준다 | 수업 1회 정리 시간 | 확인 필요 |
| H4 모드 선택 없이도 강의·실습을 구분한다 | 구분 정확도 | 테스트 4건 모두 맞게 구분 |

**5.2 고객 정의 (페르소나)** AI PM 과정 수강생이자 블로그 관리자(본인, 1순위·유일한 사용자). 종이 노트에 키워드만 적고 실습은 기록 못 해 블로그에 남기지 못함.

**5.3 마케팅 메시지** 핵심 카피 **"기억이 남아 있을 때, 질문 몇 개로 글을 완성"** · 화면 용어: AI 초안, 그냥 써줘, 이 초안 넣기

## 6. 기능적 요구사항
- F1 관리자 전용 접근: 비관리자는 로그인 화면으로, 챗봇은 관리자 확인 뒤에만 불러옴
- F2 자유 입력: 강의·실습·섞인 입력을 한 칸에, 섞여도 글 1개(관련 없으면 '강의'·'실습' 소제목)
- F3 입력 구분: 강의·실습·섞인 입력을 구분해 맞는 질문 선택
- F4 맥락 질문: 설명 빠진 부분이 있으면 초안 전에 한 번에 최대 3개, 대화당 1회, 강의는 확인형
- F5 질문 건너뛰기: "그냥 써줘" 버튼으로 바로 초안
- F6 초안 생성: 제목·요약·본문·카테고리(UI 중심=디자인, 그 외=기획)·태그 3~5개
- F7 수정 요청: "더 짧게" 등 입력 → 반영한 초안을 새 카드로
- F8 저장: "이 초안 넣기"로 칸을 채우고, 저장은 기존 임시저장·발행 버튼
- F9 대화 기록: 글마다 브라우저에 저장, 수정 시 이어서 대화(새 글은 빈 화면 + 지난 대화 불러오기)

**유즈케이스** 로그인 → AI 초안 → 메모 → 질문에 답(또는 그냥 써줘) → 수정 → 넣기 → 저장. **AI 규칙** 확인받은 뜻만 쓰고 빈칸은 "(설명 보충 필요)", 앱이 질문 수·카테고리·태그를 한 번 더 정리.
