## [실패] F-01 | 2026-11-24 | PRD 2페이지 압축 1차 시도가 3페이지에 그침
- **시도:** 섹션별 분량을 재고, 다른 섹션과 겹치는 내용(개요, OKR, 테스트 목록)을 합치고 표를 줄임
- **결과:** A4·기본 글자 크기 기준 4페이지 → 3페이지. 목표(2페이지 이하) 미달
- **원인:** 브라우저 기본 글자 크기(16px)는 약 12pt로 일반 문서(10~11pt)보다 크고,
  섹션·소제목의 위아래 여백과 표가 생각보다 공간을 많이 차지함
- **다음 조치:** "줄여도 되는 것 / 줄이면 안 되는 것" 기준을 먼저 정한 뒤 2차 압축
- **해결:** 2차 압축으로 2페이지 달성 (S-01)

## [성공] S-01 | 2026-11-24 | PRD를 A4 2페이지로 압축

  Chrome으로 PDF를 만들어 페이지 수를 바로 확인하며 고침

## [성공] S-02 | 2026-11-24 | 챗봇 응답 정리 단위테스트 통과, 비로그인 접근 차단 확인
- **시도:** AI 답변을 화면용으로 정리하는 코드(chatbot.js `parseReply`)를 단위테스트하고,
  로그인하지 않은 상태로 글쓰기 화면(write.html)에 접속
- **결과:** 단위테스트 6개 모두 통과 (질문 최대 3개, 카테고리 기획·디자인만, 태그 정리,
  빈 본문·잘못된 답변 처리). 비로그인 접속은 로그인 화면으로 이동, 콘솔 오류 없음
- **잘된 점:** AI가 규칙(질문 3개 등)을 어겨도 화면에 보여 주기 전에 코드가 한 번 더 걸러 줌

## [실패] F-02 | 2026-11-24 | 챗봇 첫 AI 호출 실패 (App Check 403, AI Logic API 미사용 설정)
- **시도:** reCAPTCHA Enterprise 키를 App Check에 등록하고 firebase-config.js에 사이트 키를 넣은 뒤,
  내 컴퓨터(localhost)에서 관리자로 로그인해 AI 초안 패널에서 테스트 메모를 보냄
- **결과:** 답변을 받지 못함. 브라우저 콘솔에 오류 2개
  - App Check 토큰 발급 403 (appCheck/fetch-status-error)
  - AI/api-not-enabled: Firebase AI API(firebasevertexai.googleapis.com)가 켜져 있지 않음
- **원인:** ① localhost에서는 reCAPTCHA 대신 디버그 토큰을 쓰는데, 그 토큰을 아직 콘솔에 등록하지 않음
  ② Firebase 콘솔 AI Logic의 "시작하기"(Gemini Developer API 사용 설정)가 끝나지 않음
- **다음 조치:** App Check에 디버그 토큰 등록, AI Logic 시작하기 완료 후 몇 분 뒤 다시 테스트.
  화면 오류 문구도 "AI Logic이 켜지지 않음"으로 구체적으로 보이게 수정함
- **해결:** 디버그 토큰 등록 후, AI Logic 화면에서 Gemini Developer API가 "사용 설정됨"인 것을 확인하고
  몇 분 뒤 다시 보내자 정상 응답 (설정 반영에 시간이 걸린 것으로 보임)

## [실패] F-03 | 2026-11-24 | 키워드만 있는 메모에 질문 없이 초안을 쓰고 일반 설명으로 빈칸을 채움
- **시도:** "PRD 작성법 - 문제 정의, AS-IS/TO-BE, OKR"처럼 설명 없는 키워드 메모를 보냄
- **결과:** 질문 없이 바로 초안을 씀. "AS-IS: 현재의 상태와 문제점을 분석합니다" 같은
  일반적인 사전 설명으로 내용을 채우고, 일부만 "(설명 보충 필요)"로 표시함
- **원인:** 지시문이 "꼭 필요한 것만 질문, 빠진 게 없으면 바로 초안"이라 AI가 질문을 건너뛸 여지가 있었고,
  일반 설명으로 채우지 말라는 규칙이 없었음
- **다음 조치:** 지시문 수정 — 설명 없는 키워드가 하나라도 있으면 반드시 먼저 질문,
  용어의 일반 설명으로 빈칸을 채우지 말고 "(설명 보충 필요)"로만 표시
- **해결:** 같은 메모를 다시 보내자 강의로 구분하고 질문 3개를 함 (S-03)

## [성공] S-03 | 2026-11-24 | 강의 메모 → 질문 3개 → 답변 → 초안 → 글쓰기 칸 넣기까지 동작
- **시도:** 내 컴퓨터(localhost)에서 관리자로 로그인해 강의 메모를 보내고, 질문에 한 번에 답한 뒤
  "이 초안 넣기"를 누름
- **결과:** 강의 내용으로 구분하고 질문 3개를 함 → 답변을 반영한 초안(제목·요약·본문·카테고리 기획·태그 5개) 생성
  → 글쓰기 칸에 제목, 본문(맨 위 "> 요약:"), 카테고리, 태그가 채워지고 "AI 초안 넣음 · 아직 저장 안 됨" 표시.
  답하지 않은 부분은 "(설명 보충 필요)"로 남음
- **잘된 점:** 저장은 기존 임시저장·발행 버튼을 그대로 써서, 기존 글 저장 기능을 건드리지 않음
- **남은 점:** AS-IS/TO-BE 답변 중 TO-BE("질문으로 맥락 채운 글")가 초안에 빠지고 "(설명 보충 필요)"로 표시됨.
  테스트 보고서에서 답변 반영률을 함께 확인할 것

## [실패] F-04 | 2026-11-24 | "새 대화", 초안 다시 넣기 버튼을 눌러도 반응 없음
- **시도:** 대화 중 "새 대화"를 누르고, 이미 넣은 초안의 버튼을 다시 누름
- **결과:** 아무 일도 일어나지 않음 (대화가 지워지지 않고, 초안도 다시 들어가지 않음)
- **원인:** 두 버튼 모두 브라우저 확인 창(confirm)으로 "지울까요?"를 묻게 되어 있었는데,
  테스트한 앱 내장 브라우저에서는 확인 창이 뜨지 않고 바로 "취소"로 처리됨
- **다음 조치:** 브라우저 확인 창 대신 패널 안에 "취소 / 새로 시작", "취소 / 바꾸기" 버튼을 직접 보여 주도록 변경.
  넣은 뒤 버튼 이름도 "넣었어요 ✓" 대신 "다시 넣기"로 바꿔 다시 누를 수 있다는 것이 보이게 함
- **해결:** 쓰던 제목·본문이 있을 때 "바꾸기" 확인 후 초안으로 교체, "새 대화" 확인 후 대화만 지워지고
  글쓰기 칸 내용은 남는 것을 확인. 완전한 실습 입력은 질문 없이 바로 초안이 나옴
  (단, Firebase 로그인 실습의 카테고리를 '디자인'으로 추천해 카테고리 추천 정확도는 테스트 보고서에서 확인할 것)
