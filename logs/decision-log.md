# 의사결정 로그

## D-01 | 2026-11-23 | 해결 방향 후보 선택
- 결정: 수업 메모 → 블로그 글 초안 챗봇 (관리자용)
- 대안: 복습 퀴즈 자동 생성, 독자용 글 Q&A 챗봇
- 이유: 직접 겪는 불편이라 근거를 대기 쉽고, 이틀 안에 구현 가능한 범위
- 영향: 이후 문제 정의를 다시 하기로 함 (D-02)

## D-02 | 2026-11-23 | 문제 정의
- 결정: 강의 메모는 짧게, 실습은 기록 없이 남아 맥락을 잃고 활용되지 못하는 문제
- 대안: "글을 안 쓴다"로 정의
- 이유: 실제로는 매 수업 쓰고 있으나, 키워드 위주라 나중에 뜻을 알 수 없음
- 영향: 핵심 기능이 "맥락 보충 질문"이 됨. 근거는 본인 기록 점검으로 수집

## D-03 | 2026-11-23 | 수업 기록 글의 카테고리
- 결정: 기존 카테고리(기획/디자인/회고) 유지, 수업 정리는 기획·디자인 중 내용에 맞게
- 대안: 'AI PM 수업 기록' 카테고리 신설
- 이유: 2일 일정에서 블로그 구조 변경보다 챗봇 구현에 집중. 회고는 수업 정리가 아닌
  경험을 돌아보는 글이므로 수업 정리 글의 카테고리로 쓰지 않음
- 영향: 챗봇이 카테고리 1개 + 태그를 추천

## D-04 | 2026-11-23 | AI 호출 방식
- 결정: Firebase AI Logic (Gemini Developer API, 무료 Spark 요금제)
- 대안: Vercel 서버리스 함수, Firebase Functions(Blaze 필요), 브라우저 직접 호출
- 이유: 서버 코드 불필요, 카드 등록 불필요, 기존 Firebase와 같은 프로젝트에서 관리
- 영향: App Check 설정, 관리자만 챗봇 표시, 테스트 일정 분산

## D-05 | 2026-11-23 | 입력 방식과 범위
- 결정: 모드 선택 없는 자유 입력(챗봇이 입력 종류 구분), 실습은 글 입력까지 포함
- 대안: 입력 종류 버튼 선택, 실습 제외, 스크린샷 입력 포함
- 이유: 입력 부담 최소화. 이미지 입력은 2일 일정에 부담
- 영향: 입력 구분 정확도를 테스트 보고서에서 반드시 검증

## D-06 | 2026-11-24 | 챗봇 범위를 회고까지 확장
- 결정: 수업 정리 + 회고 글 작성 지원
- 대안: 수업 정리만 유지 / 블로그 글 전반으로 확장
- 이유: 회고도 경험이 맥락 없이 남거나 아예 남지 않는 같은 문제이고, 질문 지침 추가
  수준이라 일정 부담이 작음. 글 전반으로 넓히면 문제 정의가 흐려짐
- 영향: PRD 3.4·4.2·5·6·9 수정, 테스트 케이스 1개 추가

## D-07 | 2026-11-24 | 회고를 이번 범위에서 제외 (D-06 변경)
- 결정: 이번 범위는 강의·실습만. 회고는 다음 단계로 이동
- 대안: 회고 포함 유지 (D-06)
- 이유: 회고 0편은 문제의 근거로 약하고, 학습조 회고는 제출 마감 이후라 기간 내 실사용
  테스트가 어려움. 입력 구분 종류와 테스트가 늘어 2일 일정에 부담
- 영향: PRD 문제 정의를 강의·실습으로 되돌림, 카테고리 추천은 기획·디자인만
